# Security policy

## Supported versions

| Version | Bug fixes | Security fixes |
|---------|-----------|----------------|
| 4.x     | ✅ | ✅ |
| 3.1     | ✅ until 4.0.0 is released | ✅ until 12 months after the 4.0.0 release |
| 3.0 and earlier | ❌ | ❌ |

## Reporting a vulnerability

**Do not open a public issue.**

Use GitHub private reporting: **Security** tab of the repository concerned → **Report a vulnerability**.

If possible, include:

- the bundle and the version concerned;
- the steps to reproduce, or a proof of concept;
- the estimated impact.

## What happens next

1. Acknowledgement within 5 business days.
2. Analysis and fix prepared in a private fork (GitHub Security Advisory).
3. Coordinated disclosure: fix release on all supported branches, security advisory published and CVE identifier requested if needed.

Please give us time to fix the issue before any public disclosure.
